# 과제 10 - 정렬 알고리즘의 성능 및 안정성 비교

`gcc -O2 -o sort_compare sort_compare.c` 로 컴파일한다. 실행하면 난수 시드를 묻고, Enter를 누르면 기본 시드(12345)로 아래 결과가 재현된다. 10,000개를 네 방법으로 100회 정렬하므로 **30초 정도 걸린다** (Visual Studio는 Release 빌드 권장).

측정 기준은 **비교** = 두 데이터의 키1을 맞대어 본 횟수, **이동** = 데이터 하나를 통째로 옮긴 횟수(교환 1회 = 이동 3회)다. 데이터 생성과 배열 복사는 세지 않는다. 네 알고리즘은 매 회 같은 원본의 복사본을 받는다.

## 1. 무작위 데이터 100회 실험

| | 총 비교 | 평균 비교 | 평균 이동 |
|---|---|---|---|
| 선택 정렬 | 4,999,500,000 | 49,995,000 | 29,971 |
| 버블 정렬 | 4,999,500,000 | 49,995,000 | 75,041,497 |
| 버블 정렬(조기 종료) | 4,998,481,737 | 49,984,817 | 75,041,497 |
| 삽입 정렬 | 2,502,382,238 | 25,023,822 | 25,033,830 |

100회 모두 오름차순 정렬에 성공했다.

선택 정렬과 버블 정렬의 비교 횟수는 데이터와 무관하게 항상 n(n-1)/2 = 49,995,000으로 **고정**이다. 두 알고리즘 모두 모든 쌍을 빠짐없이 훑기 때문이다. 삽입 정렬은 그 절반인 약 2,500만 회인데, 제자리를 찾으면 `break`로 멈추므로 무작위 데이터에서는 평균적으로 정렬된 구간의 절반만 비교하기 때문이다.

이동 횟수에서는 차이가 극적이다. 선택 정렬은 한 번 훑을 때 교환을 최대 한 번만 하므로 평균 약 3만 회(교환 약 1만 회)에 그치지만, 버블 정렬은 7,500만 회로 **2,500배** 많다. 인접한 쌍을 하나씩 밀어내며 옮기기 때문이다. 즉 선택 정렬은 "비교는 많지만 이동이 매우 적은" 정렬이다.

**조기 종료의 효과는 무작위 데이터에서 거의 없다.** 4,999,500,000에서 4,998,481,737로 0.02% 줄었을 뿐이다. 10,000개가 무작위로 섞여 있으면 마지막 순회에 가서야 교환이 멈추므로 일찍 끝날 기회가 사실상 없다. 조기 종료는 **이미 정렬에 가까운 입력**에서만 의미가 있다.

## 2. 입력 상태별 성능

| | 정렬된 데이터 | | 역순 데이터 | | 일부 정렬 데이터 | |
|---|---|---|---|---|---|---|
| | 비교 | 이동 | 비교 | 이동 | 비교 | 이동 |
| 선택 정렬 | 49,995,000 | 0 | 49,995,000 | 15,051 | 49,995,000 | 1,512 |
| 버블 정렬 | 49,995,000 | 0 | 49,995,000 | 149,984,850 | 49,995,000 | 9,455,811 |
| 버블(조기 종료) | **9,999** | 0 | 49,995,000 | 149,984,850 | 49,977,045 | 9,455,811 |
| 삽입 정렬 | **9,999** | 19,998 | 49,995,000 | 50,014,948 | **3,161,936** | 3,171,935 |

**이미 정렬된 데이터.** 삽입 정렬과 조기 종료 버블 정렬만 9,999회(= n-1)로 끝난다. 삽입 정렬은 매 데이터가 바로 앞 데이터보다 크므로 첫 비교에서 바로 멈추고, 조기 종료 버블은 첫 순회에서 교환이 한 번도 없어 즉시 끝난다. 반면 선택 정렬과 일반 버블 정렬은 이미 정렬되어 있는데도 똑같이 약 5천만 회를 비교한다. 입력 상태를 전혀 활용하지 못하는 것이다. 삽입 정렬의 이동 19,998회는 임시 변수 저장과 제자리 되쓰기(데이터당 2회)이며 실제로 자리가 바뀐 것은 없다.

**역순 데이터.** 최악의 경우다. 삽입 정렬의 비교가 9,999회에서 49,995,000회로 **5,000배** 늘어 선택·버블과 같아진다. 모든 데이터가 정렬 구간 전체를 끝까지 밀고 가야 하기 때문이다. 버블 정렬의 이동은 1억 5천만 회로, 비교할 때마다 거의 매번 교환이 일어난 결과다(49,994,950회 교환 × 3). 조기 종료도 교환이 끝까지 발생하므로 전혀 도움이 되지 않는다. 눈에 띄는 것은 **선택 정렬의 이동이 15,051회뿐**이라는 점인데, 역순이든 무작위든 교환 횟수가 최대 n-1로 묶여 있기 때문이다.

**일부 정렬 데이터.** 삽입 정렬이 316만 회로 무작위(2,500만 회)의 1/8까지 떨어진다. 대부분의 데이터가 이미 제자리 근처에 있어 몇 번만 비교하고 멈추기 때문이다. 반대로 선택·버블 정렬은 여전히 약 5천만 회로 꿈쩍하지 않는다. 조기 종료 버블은 9,810번째 순회에서 멈춰 0.04%만 아꼈다. **섞인 원소가 배열 앞쪽에 하나라도 남아 있으면 그것이 제자리로 갈 때까지 교환이 계속되므로** 조기 종료 조건이 걸리지 않는다.

**부분 정렬 데이터를 만든 방법.** AI(Claude)에게 부분 정렬 데이터 생성법을 물어 세 가지 방식(① 정렬된 배열에서 무작위 두 자리 교환, ② 일정 구간만 섞기, ③ 정렬된 값에 작은 잡음 더하기)을 조사했고, 그중 ①을 선택했다. **정렬이 끝난 10,000개 배열에서 무작위 두 위치를 교환하는 작업을 500회(데이터 수의 5%) 수행**했다. 교환 횟수 하나로 흐트러진 정도를 조절할 수 있고 "5% 교란"처럼 설명하기 쉬워서 선택했다. ②는 구간 경계에서 성질이 급변해 해석이 복잡하고, ③은 키 값 자체를 바꿔 원본과 같은 데이터가 아니게 되는 문제가 있었다.

## 3. 안정성 검증

**검증 방법.** 각 데이터에 원래 입력 순서를 나타내는 `index`를 저장해 두고(정렬 기준에는 쓰지 않음), 정렬 후 **키1이 같은 이웃끼리 index가 거꾸로 된 곳이 하나라도 있으면 불안정**으로 판정했다. 무작위 데이터는 키1 범위가 0~1,000,000이라 중복이 거의 없으므로, 검증용으로 **데이터 1,000개에 키1을 0~19만 사용해** 중복을 대량으로 만든 별도 입력을 사용했다.

| 정렬 | 결과 |
|---|---|
| 선택 정렬 | **Unstable** |
| 버블 정렬 | Stable |
| 삽입 정렬 (>) | Stable |
| 삽입 정렬 (>=) | **Unstable** |

**선택 정렬이 불안정한 이유.** 최솟값을 찾으면 **멀리 떨어진 자리와 통째로 교환**하는데, 이때 교환되어 뒤로 밀려난 데이터가 자기와 키가 같은 다른 데이터를 뛰어넘을 수 있다. 예를 들어 `(5,a) (5,b) (1,c)`에서 첫 단계에 1과 맨 앞 (5,a)가 교환되면 `(1,c) (5,b) (5,a)`가 되어 a와 b의 순서가 뒤집힌다. 교환 거리가 멀다는 것이 불안정의 원인이다.

**버블 정렬이 안정한 이유.** 인접한 쌍만 다루고 조건이 `>`(엄격한 큼)이라서 **키가 같으면 교환하지 않는다.** 같은 키끼리는 서로를 절대 넘어가지 않는다.

**삽입 정렬의 `>`와 `>=` 차이.** 이것이 이번 과제에서 가장 분명한 부분이다.

```
원본           : (527,100) (527,200) (125,300) (892,400)
삽입 정렬 (>)  : (125,300) (527,100) (527,200) (892,400)   ← 순서 유지
삽입 정렬 (>=) : (125,300) (527,200) (527,100) (892,400)   ← 뒤집힘
```

`>`는 "앞의 데이터가 **더 클 때만**" 밀어내므로, 키가 같으면 즉시 멈추고 현재 데이터가 **같은 키의 뒤에** 놓인다. 원래 순서가 그대로 유지된다. 반면 `>=`는 키가 같아도 밀어내므로 현재 데이터가 같은 키 무리를 전부 뚫고 **맨 앞까지** 가버린다. 나중에 온 데이터가 먼저 온 데이터 앞에 서게 되어 순서가 뒤집힌다. 같은 알고리즘인데 **부등호 한 글자가 안정성을 바꾼다.**

부수적으로 `>=`는 멈출 수 있는 곳에서도 계속 밀어내므로 비교와 이동이 더 많아져 성능에도 손해다.

## 4. 정리

초기 상태를 활용할 수 있는가가 성능을 가른다. 삽입 정렬은 입력이 정렬에 가까울수록 빨라져(9,999회 ~ 5천만 회) 폭이 5,000배에 이르지만, 선택 정렬과 일반 버블 정렬은 **어떤 입력이든 항상 n(n-1)/2회**로 고정이다. 비교 구조상 입력을 보고 일을 줄일 여지가 없기 때문이다. 조기 종료 조건은 이 약점을 일부 보완하지만, 완전히 정렬된 입력에서만 극적인 효과(5천만 → 9,999)를 내고 무작위나 일부 정렬 입력에서는 0.05% 미만의 개선에 그쳤다.

이동 횟수로 보면 선택 정렬이 모든 입력에서 가장 적다(최대 3만 회). 데이터 하나의 크기가 커서 복사 비용이 비싼 상황이라면, 비교가 많더라도 선택 정렬이 유리할 수 있다.
